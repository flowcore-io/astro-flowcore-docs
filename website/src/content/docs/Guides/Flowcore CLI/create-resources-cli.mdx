The Flowcore CLI creates Data Cores, Flow Types, and Event Types. Use one command for an individual resource or apply a manifest when the resources belong together.

## Apply a Data Core manifest

Generate a starter manifest:

```sh
flowcore data-core init --tenant example-tenant
```

Edit `flowcore.yaml`:

```yaml
tenant: example-tenant
dataCore:
  name: example-data-core
  description: Example application events
  flowTypes:
    users:
      description: User lifecycle
      eventTypes:
        user.created.0:
          description: A user was created
```

Preview and apply the manifest:

```sh
flowcore data-core apply --file flowcore.yaml
```

Use the root command when a file contains several supported resources:

```sh
flowcore apply --file flowcore.yaml
```

## Create resources individually

```sh
flowcore data-core create example-data-core --tenant example-tenant

flowcore flow-type create users \
  --tenant example-tenant \
  --data-core example-data-core

flowcore event-type create user.created.0 \
  --tenant example-tenant \
  --data-core example-data-core \
  --flow-type users
```

Run `flowcore <command> --help` before scripting a command to see the options supported by your installed CLI version.

## Delete protection

Set `deleteProtection: true` on a Data Core when it must not be deleted accidentally. Protected nested resources cannot be deleted until protection is disabled.

```yaml
tenant: example-tenant
dataCore:
  name: example-data-core
  deleteProtection: true
```

## Sensitive Data configuration

An Event Type can opt into Sensitive Data handling in the manifest:

```yaml
tenant: example-tenant
dataCore:
  name: example-data-core
  flowTypes:
    users:
      eventTypes:
        user.created.0:
          sensitiveDataEnabled: true
          sensitiveDataKey: ".userId"
          sensitiveDataSchema: |
            {
              "email": { "faker": "internet.email" },
              "ssn": { "redact": { "char": "*", "length": 9 } }
            }
```

See [Sensitive Data concepts](/guides/sensitive-data/concept/) for schema options.

## V2 Resources

IAM resources use their dedicated CLI commands. See the [IAM guide](/guides/iam/getting-started/) for policies, roles, and assignments.

Application delivery is configured with [Flowcore Pathways](/guides/flowcore-pathways/), not resource manifests.
